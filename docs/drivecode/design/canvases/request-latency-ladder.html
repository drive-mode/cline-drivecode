Scored against Drive

The ladder describes a tiered web service: browser → edge → app server → pool → SQL → downstream services. Drive's hot path is a single-writer daemon on 127.0.0.1 speaking one persistent WebSocket, folding an append-only event log in memory. Most of these cost centres are not there.

The measured one

Fix 6 is the only rung Drive already built, so it is the only one that can be scored rather than reasoned about. The mermaid content-hash SVG cache measures 1.2× — cold 0.0076 ms, warm 0.0062 ms — because the warm path still hashes, base64-encodes and rebuilds the item, and elides only a stub SVG wrapper. The cache is correctly placed for a cost that does not exist yet.

Which is the ladder's real lesson, and it is not one of its six slides: the power comes from the profile, not the fixes.
