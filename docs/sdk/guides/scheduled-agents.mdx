Cline supports recurring and one-shot agent runs. There are **two scheduling paths** — pick the one that matches your host:

| Path | Who uses it | Surface |
|------|-------------|---------|
| **Hub `schedule.*` (product-canonical)** | CLI, Hub dashboard, Desktop routines | Hub WebSocket commands + `HubSessionClient` schedule methods |
| **`cline.automation` (embedder / SDK-local)** | Custom apps embedding `ClineCore` without Hub schedule UI | File-based cron specs + `ClineCore.create({ automation: true })` |

Product hosts (CLI / Hub / Desktop) **do not** create schedules through `cline.automation`. That API is the embedder alternative for in-process file/event automation. Do not treat the two stores as interchangeable.

Scheduled product runs rely on the [hub-spoke architecture](/sdk/architecture/hub-spoke). The hub daemon persists Hub schedules across restarts and executes them when no client is attached.

## Product path: CLI + Hub `schedule.*`

### Schedule wizard

An easy way to manage schedules is the Cline CLI (install via `npm i -g cline` or run from this monorepo with `bun run cli`).

Run `cline schedule` for an interactive menu: create/list schedules, trigger now, pause/resume, execution history, and stats.

### Creating schedules with flags

```bash
# Daily at 9 AM on weekdays
cline schedule create "PR summary" \
  --cron "0 9 * * MON-FRI" \
  --prompt "List all open PRs, their review status, and any that have been open more than 3 days" \
  --workspace /path/to/repo \
  --model anthropic/claude-sonnet-4-6

# Every 6 hours
cline schedule create "Health check" \
  --cron "0 */6 * * *" \
  --prompt "Run the test suite and report any failures" \
  --workspace /path/to/project

# Monday mornings
cline schedule create "Weekly digest" \
  --cron "0 8 * * MON" \
  --prompt "Summarize last week's commits, PRs merged, and issues closed"
```

The CLI ensures a local hub is running, then issues Hub commands such as `schedule.create`, `schedule.list`, `schedule.trigger`, `schedule.disable` / `schedule.enable`, and `schedule.delete`.

### Managing schedules

```bash
cline schedule list
cline schedule trigger <schedule-id>
cline schedule pause <schedule-id>
cline schedule resume <schedule-id>
cline schedule delete <schedule-id>
cline schedule executions <schedule-id>
```

See also the CLI guide: [Scheduling](/cli/scheduling).

### Programmatic Hub schedules

Hosts and embedders that talk to the hub can use `HubSessionClient` (from `@cline/sdk` or `@cline/core/hub`). Ensure a hub is reachable (CLI/`ensureDetachedHubServer` starts one when needed), then call schedule methods that map 1:1 to Hub `schedule.*` commands:

```typescript
import {
  ensureDetachedHubServer,
  HubSessionClient,
} from "@cline/sdk"

const hub = await ensureDetachedHubServer(process.cwd())
const client = new HubSessionClient({
  address: hub.url,
  authToken: hub.authToken,
  clientId: "my-scheduler",
  workspaceRoot: process.cwd(),
})

try {
  const schedule = await client.createSchedule({
    name: "PR summary",
    cronPattern: "0 9 * * MON-FRI",
    prompt: "List open PRs and their review status",
    workspaceRoot: process.cwd(),
    mode: "yolo",
  })

  await client.listSchedules()
  if (schedule?.scheduleId) {
    await client.triggerScheduleNow(String(schedule.scheduleId))
  }
} finally {
  client.close()
}
```

| Client method | Hub command |
|---------------|-------------|
| `createSchedule` | `schedule.create` |
| `listSchedules` | `schedule.list` |
| `getSchedule` | `schedule.get` |
| `updateSchedule` | `schedule.update` |
| `pauseSchedule` | `schedule.disable` |
| `resumeSchedule` | `schedule.enable` |
| `deleteSchedule` | `schedule.delete` |
| `triggerScheduleNow` | `schedule.trigger` |
| `listScheduleExecutions` | `schedule.list_executions` |

Create payloads follow `HubScheduleCreateInput` in `@cline/shared` (`name`, `cronPattern`, `prompt`, `workspaceRoot`, optional `mode`, `modelSelection`, limits, tags, metadata).

## Embedder path: `cline.automation`

Use this when you embed `ClineCore` and want **SDK-local** cron/event automation (Markdown specs under `~/.cline/cron/` or a workspace `.cline/cron/`), not the Hub schedule store that CLI/Desktop/Hub UI manage.

```typescript
import { ClineCore } from "@cline/sdk"

const cline = await ClineCore.create({
  clientName: "scheduler",
  automation: true,
})

await cline.automation.start()
await cline.automation.reconcileNow()

const specs = cline.automation.listSpecs()
const runs = cline.automation.listRuns()

await cline.automation.stop()
await cline.dispose()
```

| Method | Role |
|--------|------|
| `start` / `stop` | Start or stop the in-process cron automation service |
| `reconcileNow` | Re-read specs from the configured cron directory |
| `ingestEvent` | Push an external event into matching event-triggered specs |
| `listSpecs` / `listRuns` / `listEvents` | Inspect reconciled specs, runs, and ingested events |

File-based specs support `trigger: schedule | one_off | event`. Example recurring spec:

```markdown
---
trigger: schedule
schedule: "0 9 * * MON-FRI"
timezone: America/New_York
mode: exclusive
prompt: "Check for dependency updates and create PRs for outdated packages."
modelSelection:
  providerId: anthropic
  modelId: claude-sonnet-4-6
tools:
  enabled: true
---

Additional context for the agent goes in the body.
```

Concurrency: `mode: exclusive` skips overlapping runs; `concurrent` allows them. Completed runs write reports under `.cline/cron/reports/`.

The Hub daemon may also optionally start a file-based `CronService` via hub `cronOptions` — that is still the **automation/spec** path, parallel to Hub `schedule.*` product schedules. Do not migrate product Hub schedules onto `cline.automation` without an explicit product decision.

## Cron expression reference

| Expression | Schedule |
|-----------|----------|
| `0 9 * * MON-FRI` | 9 AM, Monday through Friday |
| `0 */6 * * *` | Every 6 hours |
| `0 8 * * MON` | 8 AM every Monday |
| `30 17 * * *` | 5:30 PM every day |
| `0 0 1 * *` | Midnight on the 1st of each month |
| `*/30 * * * *` | Every 30 minutes |

## Use cases (CLI / Hub schedules)

### Daily standup summary

```bash
cline schedule create "Standup prep" \
  --cron "0 8 * * MON-FRI" \
  --prompt "Summarize: (1) PRs merged yesterday, (2) PRs currently in review, (3) open issues assigned to team members. Format as a brief standup update." \
  --workspace /path/to/repo
```

### Automated dependency updates

```bash
cline schedule create "Dependency check" \
  --cron "0 10 * * MON" \
  --prompt "Check for outdated npm dependencies. For any with security vulnerabilities, create a branch with the update and open a PR." \
  --workspace /path/to/project
```

### Codebase health report

```bash
cline schedule create "Code health" \
  --cron "0 6 * * MON" \
  --prompt "Analyze the codebase for: (1) files with no test coverage, (2) TODO/FIXME comments older than 30 days, (3) functions longer than 100 lines. Produce a health report." \
  --workspace /path/to/project
```

## Concurrency and resource limits

For **Hub schedules**, concurrency is controlled per schedule (`maxParallel` and related runtime options). If a previous execution is still running when the next trigger fires, behavior follows those limits (queue or skip). The hub coordinates execution through spokes.

For **`cline.automation` specs**, use `mode: exclusive | concurrent` on the Markdown front matter as described above.

## Routing results

Combine Hub/CLI scheduled agents with [connectors](/cli/connectors) to route results to messaging platforms:

```bash
# Start a Telegram connector
cline connect telegram -k $BOT_TOKEN

# Schedule an agent whose output gets sent to Telegram
cline schedule create "Morning briefing" \
  --cron "0 8 * * *" \
  --prompt "Summarize overnight activity in the repo"
```
