# SDK integration build

**Public SDK:** [docs.cline.bot/sdk/overview](https://docs.cline.bot/sdk/overview) — `npm install @cline/sdk` (Node ≥22). Same harness as Cline IDE/CLI: plugins, checkpoints, MCP, cron, subagents, and more.

**Visual plan (primary):** open the Tldraw canvas in this Cursor session (`canvasId: giaumqy8`) — package map, leverage heatmap, decision diamonds D1–D4, phase strip, agent swimlanes, and kickoff order.

**Companion detail:** task acceptance criteria below (and [Usage analysis](/sdk/architecture/usage-analysis)).

Turns usage analysis into a sequenced build against the **advertised public SDK** (`ClineCore` / `Agent`, tools, plugins, multi-agent, scheduled agents, production budgets). Phases are ordered by dependency — **no calendar estimates**. Each **agent task** is one focused PR.

**Source of truth for symbols:** code (`DefaultToolNames`, `TEAM_TOOL_NAMES`, `ClineCore` APIs) + [public docs](https://docs.cline.bot/sdk/overview) — not stale skill text when they drift.

## North star

Product hosts stay on **`ClineCore`** from `@cline/sdk` / `@cline/core`. We do **not** migrate hosts to bare `Agent` unless embedding a lightweight loop. Success means:

1. Hosts share **one defaults story** for multi-agent, plugins-on-session, budgets, and Hub runtime depth.
2. Public docs surfaces either **match product paths** or docs name the product-canonical alternative (esp. scheduling vs `cline.automation`).
3. An agent can pick any open task and land it without inventing product policy.

## Non-goals (whole build)

- Replacing host adapters (VS Code terminal/diff/`McpHub`, Hub WS protocol) with a thin SDK client.
- Adopting `backendMode: "remote"` or browser automation without a separate product decision.
- Moving product hosts onto umbrella-only imports for its own sake (peers `@cline/core` etc. remain fine in-monorepo).
- Rewriting evals to construct SDK objects (CLI/Harbor behavioral coverage is enough).

## Decision gates (lock before coding)

Agents must **stop and surface** these if still open. Defaults below are the proposed lock; change them here (and on the visual plan) before implementing dependent tasks.

| ID | Decision | Proposed lock | Unlocks |
|----|----------|---------------|---------|
| **D1** | Multi-agent host defaults | **CLI non-YOLO semantics** as product default: `enableSpawnAgent: true`, `enableAgentTeams: true` unless YOLO/sandbox/ACP special-cases. Hub Chat and Desktop adopt the same defaults. VS Code: enable behind a user/setting flag defaulting **on** once UI is honest; until then do not leave dead subagent UI. | Phase 2 |
| **D2** | Scheduling canonical path | **Hub schedule services / `schedule.*` commands** are product-canonical. Public [scheduled-agents](https://docs.cline.bot/sdk/guides/scheduled-agents) docs must lead with that path; `cline.automation` documented as the embedder/SDK-local alternative — not as “what Desktop/CLI use.” | Phase 3 |
| **D3** | Plugin session injection | Installed/enabled plugins load into `CoreSessionConfig` via `pluginPaths` / `extensions` + `extensionContext.workspace` on session start (matches [plugins](https://docs.cline.bot/sdk/plugins) guide). | Phase 4 |
| **D4** | Cost budgets | Shared defaults for `maxIterations` (+ optional usage abort) per [going-to-production](https://docs.cline.bot/sdk/guides/going-to-production); hosts may override. | Phase 5 |
